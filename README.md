# JusBuddy · DSH 插件 0.2.19

在 DSH 官方客户端内提供智链业务入口、已授权 MCP 工具、个人技能与 HTML 成果查看。通过独立 Plugin/Bundle 和 UI Slots 接入，不修改 DSH 安装包。智链业务请求使用当前企业的 UAT 授权。业务工具由桌面端的智链 MCP 连接提供。

## 安装与更新

在 DSH「插件 → 添加插件」粘贴：

```text
https://github.com/Easton2026/juslink-dsh-agent-center.git
```

需要固定版本时，在地址后加 `#` 和本仓库完整提交标识。已安装旧版时，在插件页卸载旧版再添加新版，启用并按 DSH 提示重载或重启。需要安装电脑能够访问 GitHub；模型继续使用安装者自己的 DSH 配置。

## 工作区授权

打开 JusBuddy 直接进入工作台。顶部企业菜单从本机读取已保存的企业授权。操作需要连接智链时，插件会在后台校验当前企业的授权并尝试续期。需要登录时，从企业菜单打开浏览器完成授权。

登录使用新的 PKCE 和 state，并在本机回调。凭证由 DSH 凭据服务保存。当前网关为 UAT 的 `juslink-api-gateway-uat`，网关证书链校验失败时会尝试同一 UAT 网关的 HTTP 入口。登录、注册与换取令牌使用 HTTPS。

## 当前功能

- **智链工具**：默认入口，三列响应式纯文字工具卡片，展示现有五项天眼工具入口，业务访问以当前企业授权为准。点击「搜索订阅」进入对话，在该对话内查看查询结果与物流卡片。
- **场景专家**：平台和个人专家统一展示，采用白底介绍卡片和右下角专属图形，个人专家右上角标记，点击卡片发起对话，简介下方独立查看详情入口展开场景能力和涉及工具，支持对话式新建、编辑及确认删除；平台包含物流综合分析、运输异常跟进。
- **我的技能**：平台和个人技能统一展示，个人技能右上角标记，点击简介下方查看详情展开完整正文，无顶部装饰图标，个人技能支持对话式编辑、确认删除及新增。技能仍由 DSH 原生机制调用。

页面入口名称以当前源码为准。场景专家目前通过指令组合可用工具，尚无可视化专家配置器、自动排程或企业多租户隔离。

## 新建个人场景专家

在“场景专家”点击“新建场景专家”，自动打开 DSH 新对话并提交 `/juslink-create-personal-expert` 创建指令。DSH 先询问要解决的问题；用户描述目标后，梳理必要输入、匹配实际可用的工具，形成步骤、判断规则、异常处理、完成条件与输出要求。缺少能力时说明缺口，不虚构接口。

确认方案并同意保存后，DSH 通过正常文件工具保存并读回核对；试跑为可选步骤。保存需遵守宿主现有审批，待审批或失败时不算已创建。保存成功返回“场景专家”即可查看；点击专家卡片会新开对话并询问本次所需信息，不默认填入演示单号。

专家为当前 DSH 用户根目录 `skills/juslink-expert-<唯一标识>/SKILL.md` 下的原生文件 Skill（DSH_HOME 或默认用户 .dsh），metadata 包含 plugin、scope: personal 和 kind: scenario-expert。description 为“【中文名】用途”。因为宿主目录接口不返回 metadata，页面使用专用名称前缀和文件位置区分个人专家与普通技能，这是展示约定，不是权限隔离；不会修改平台专家、随插件上传个人文件或跨设备同步。

个人专家及个人技能在新建和编辑时，由 Agent 根据完整内容提炼约 30～45 个汉字的卡片简介，使用原有 description 归属格式保存；页面最多显示两行，超出省略，已有文件不自动重写。新建和编辑流程保存 metadata.scene_capability（自然语言能力描述）及 metadata.tool_names（英文逗号分隔的完整工具标识），旧专家从实际正文的目标、范围、输出等内容及明确工具标识识别，不补造工具。详情工具清单不是授权状态。编辑通过新对话更新原文件，删除沿用本机文件校验、二次确认及版本检查，仅移除对应 SKILL.md。创建流程注册为用户显式调用的内部 Skill，不自动由模型触发。专家每次执行需重新核对工具可用性：数据缺失、工具停用、调用失败时报告缺口；不提供定时调度或无人值守运行。

## 业务查询

在 DSH 对话中输入业务类型和单号，例如“查海运提单”加完整号码。插件直接在这轮对话下展示真实查询结果，有节点时可展开核对实际与预计时间。DSH 使用智链 UAT MCP 查询当前企业可见的记录。查不到时可核对号码类型和授权范围。

## 个人技能

点击技能页“新增”，DSH 会询问用途和方法，再通过其文件工具保存原生 SKILL.md；文件操作遵守 DSH 的现有权限与审批流程。平台内置方法随插件提供，个人文件独立保存，更新插件不会覆盖。

智链个人技能采用专用名称前缀 `juslink-personal-`，目录与名称相同，YAML metadata.plugin 为 `@juslink/agent-center-ui`、scope 为 personal；description 使用“【中文名】用途”格式。当前页面按专用命名空间及文件位置筛选，这只是显示归属，不是原生插件权限绑定或多用户隔离。其他技能不会自动被归入智链。展开个人技能读取实际 SKILL.md 正文，与平台技能一致。点击编辑打开新 DSH 对话并显式调用内部编辑 Skill，按用户确认的方案更新原文件；返回页面后重新读取目录及已展开正文。删除在页面二次确认后通过本机接口移除对应 SKILL.md，非空目录及其余文件保留。读取与删除只接受当前 DSH 用户技能根目录中的专属名称、普通文件及匹配的归属 metadata；拒绝其他路径、链接及平台技能。删除前校验正文版本，避免误删已修改内容。若宿主与 Agent 文件系统不一致或目录不可读，页面明确报错。

## HTML 成果

生成 HTML 后，可明确要求“保存到成果中心”，调用 `juslink_artifact_save`。也可显式使用 `/juslink-artifact-publish`。

保存位置为当前会话工作目录下的 `juslink-artifacts/<标识>/index.html`，`index.json` 保存标题、摘要、时间及大小。保存成功以工具返回值为准；仅生成一个本地 HTML 或在聊天中展示，并不会自动进入索引。

可以从当前 DSH 工作区按返回路径打开成果。HTML 应自包含、样式内联；单个文件上限 2 MB。成果不会同步到其他电脑或自动上传 GitHub。

## 已知限制

- 多个对话同时向同一目录保存成果时，当前索引更新会发生冲突；请暂时逐个保存。
- 成果发布 Skill 已注册到 DSH，但当前我的技能页的平台技能只展示运输分析方法。
- 对话、任务与成果尚未建立完整的自动回流与状态恢复机制。
- macOS 官方 DSH 0.2.2-rc.3 已验证工具调用、技能创建回显和成果 iframe 预览；旧版完整桌面流程和 Windows 尚未实测。

兼容声明为 `0.2.1-rc.5 || >=0.2.2-rc.1 <0.3.0`。声明不等于已验证该范围内所有功能，也不承诺未来版本自动兼容。

## 源码与构建

本仓库包含完整前端源码、品牌资源和运行文件，无需下载第三方依赖。使用现代 Node.js 执行：

```sh
node build.mjs
node --check index.js
node --check client.js
```

`src/` 是前端源码，`assets/` 是构建资源，`client.js` 是已构建的客户端入口。运行包由 package.json 的 files 清单决定，包含 `artifact-store.js` 及其余工具、技能模块。

可在源码目录通过官方 CLI 本地开发安装：`dsh plugin --profile desktop add <本地目录>`。

可选生成 npm 兼容 TGZ 与 ZIP：

```sh
python3 release/package_release.py --output /tmp/juslink-release
```

打包脚本从同一个 files 清单取文件，排除个人技能、成果目录、备份、账号、凭据和本机状态。发布说明不包含任何真实业务数据。
